# 风扇实例管理与硬件控制代码收口计划

日期：2026-11-20（覆盖 11 月 19 日夜间至 20 日凌晨的问题）
状态：软件收口及本地模拟回归已完成，等待真机统一验收；工作区尚未提交、推送或部署。

## 1. 收口目标与边界

保持解耦架构：Studio → Device Agent → 独立驱动客户端 → fanctl → PWM/FG。
fanctl 是唯一硬件控制者、温控策略执行者与实例清单持久化所有者。Agent 和独立驱动不得再直接写 PWM/GPIO，不得生成默认双风扇或执行第二套温控循环。单/多实例共用相同驱动，实例由配置决定。

本轮先完成软件修复、模拟回归与部署说明。真机接线、波形、RPM 绝对精度及整机散热验收留至用户下一轮统一验证。不得远程部署、自动改线序配置、清空设备实例清单或发送整机运动命令。

## 3. 分阶段执行计划

### 阶段 A：统一独立驱动与 Agent 适配器

仓库：zelux-device-drivers、zelux-device-agent。

- 保留独立驱动服务客户端修复；全路径使用 instance_id，整数索引只作基于服务清单的兼容入口。
- 核对 Agent HAL 实际加载路径、包位置、驱动版本和 fallback 状态；不再假定内置适配器就是生产实现。
- 对齐独立包与内置 fallback 的请求、错误码和异常翻译，避免不同 FanUnavailable 类型导致漏捕获。
- 快照明确区分已配置实例 inventory.instances、运行状态 items、服务可达性、硬件健康和测速可用性。
- 驱动启动时服务不可达应能随后恢复；无实例不应虚构硬件，后台任务在停止时正确回收。

验收：稳定 ID 调速/读取/自检/CRUD 均通过；零实例无默认双风扇；拒绝响应不会被包装成成功；独立包与 fallback 一致。

### 阶段 B：PWM 初始化与释放安全性

仓库：zelux-fan。

- 当前 period=0 时先写有效 period，再写目标 duty，最后 enable；已有有效周期时按旧 duty 与新 period 的约束安全调整。
- 不再无条件吞掉 disable 写入失败；错误附带实例、操作、属性和原因，避免继续写入未知硬件状态。
- 节点确实不存在时，禁用/删除允许清理无效配置并释放服务确实拥有的 FG 资源，返回“节点不存在，无需停止”的结果。
- 节点存在但停止失败、权限错误或状态无法确认时继续失败关闭，不冒充资源已释放。
- 持久化失败回滚内存及可恢复输出；恢复输出本身失败时保留原始错误及恢复错误，不相互覆盖。
- 保持只使用预导出 PWM 的现有边界，不擅自 export/unexport，也不从失效的显式映射猜其它通道。

验收：模拟 sysfs 覆盖零周期、周期升降、停止失败、缺失节点、测速释放失败与持久化回滚；每条成功/失败响应均准确。

### 阶段 C：测速后台化，状态请求不阻塞

仓库：zelux-fan，必要时配合独立驱动。

- 将 FG 测速从 info()/status() 的同步采样改为后台采样，状态只读取缓存。
- 缓存按实例关联，包含 RPM、采样时间/新鲜度和不可用原因；无样本/过期用未知值，不能误报 0 RPM。
- 采样不在库存锁下持续等待；删除、禁用、换 FG 时终止或隔离旧采样，避免重新导出已释放 GPIO或把旧值写入新配置。
- 多实例采样有界并发；不让多颗风扇把状态查询耗时串行累加。
- 对其余同步硬件操作、写盘和 selftest 排查阻塞路径；耗时操作与 socket 事件循环隔离，并维持一致的锁和事务边界。
- 超时按操作区分，但不把单纯延长等待当作后台化的替代方案。

验收：模拟慢测速时 ping/status 仍及时返回；删除后无残留采样或资源重占用；服务退出正确回收任务；并发请求不会死锁。

### 阶段 D：命令结果、刷新失败与 Studio 状态收口

仓库：zelux-device-drivers、zelux-device-agent、zelux-studio。

- 分开处理“操作已被服务确认成功”和“后续状态刷新失败”。已确认保存但刷新失败应提示已保存、状态待刷新。
- 命令本身超时则结果未知，不得宣称成功或失败已回滚；重查服务清单/状态，避免自动重放 create 等写操作。
- 需要时返回状态新鲜度/刷新警告字段；任何跨仓库字段变更先补契约说明及兼容约定。
- 保存成功后先清理草稿，再合并服务状态并渲染，避免同步订阅仍展示旧草稿；页面离开后异步响应不得污染其它页面或丢掉其它模块状态。
- 手动目标值、实际 PWM 占空比、RPM、自动/手动模式与测量未知状态区分展示。停止自动刷新覆盖正在操作的输入，保持控件焦点稳定。
- 禁用/删除后立即合并权威状态；部分资源释放失败不得提示全成功。

验收：模拟已保存后刷新失败、创建超时但实际已保存、重复点击、离页响应、断连/重连及高频推送，确保提示不误导且无闪烁。

### 阶段 E：统一验证、记录与交付

- 运行 fanctl socket/事务测试、独立驱动契约测试、Agent 风扇 API 测试及 Studio DOM 回归；明确缺失依赖、未执行项，不以语法检查冒充功能验收。
- 增加跨层测试：Studio 格式实例 ID → Agent → 实际独立驱动 → 模拟 fanctl；重点覆盖正式包加载路径。
- 每阶段完成后记录实际改动、命令、结果、风险和未完成项；不提前把计划标成已完成。
- 复核 git diff，保留现有工作区修改，不提交 __pycache__ 等运行产物，不改其它设备功能。
- 给出各仓库提交/版本对应关系和设备实际 Python 环境更新方式，避免只更新源码却仍加载旧包。
- 统一提交/推送及设备部署按用户明确授权执行；本计划不代表已提交或已部署。

## 4. 下一轮统一真机测试

1. 用户确认实际 PWM/FG 线序、主控物理脚位、pwmchip 对应控制器和每转脉冲数；没有确认前不固化默认引脚。

3. 30% / 90% 短时调速，检查 sysfs 与实物响应；完成后恢复自动温控并关注主控温度。
4. RPM 随转速变化；无测速/采样过期展示未知，测速过程不造成 UI 超时。
5. 有效实例启用/禁用/删除回归；无效 PWM 实例可以清理，真实写失败仍正确拒绝。
6. 页面刷新、Agent 重启、fanctl 重启后清单一致；旧双风扇不会凭空再生；重启恢复自动温控。
7. 断连或延迟不会诱导重复创建，命令结果及刷新警告可区分。

涉及输出停止或低速测试需用户确认散热保障；不进行自动整机运动测试。验收证据包括组件版本/包位置、实例清单、sysfs 读数、服务日志及用户实物观察。

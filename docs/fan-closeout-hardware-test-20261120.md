# 风扇收口统一真机测试

状态：软件模拟回归已完成，本文是待执行方案，不是设备验收结果。测试期间不发送机器人运动指令。PWM 引脚首次启用和资源所有权现按本文新增的 Studio 配置流程验收，不要求用户手工预 export。

## 测试前

1. 确认散热保障、主控温度与紧急停止方式。禁用/删除会停止输出，不可长时间失去散热。
2. 记录 fanctl 1.1.1、独立驱动 1.2.1、Agent 和 Studio 的实际部署版本与提交号。设备上用 Agent 实际 Python 解释器查看 zelux_drivers.__file__ 和 __version__，不能只检查源码目录。同步部署所有相关仓库，不自动删除原实例。
3. 备份 /var/lib/zelux-fan/inventory.json 和 /etc/zelux/zelux.toml；确认实际 service 的路径和环境配置，路径以 systemctl cat zelux-fand 为准。
4. 核对主控物理脚位、pwmchip 对应控制器、风扇 PWM/FG 线序和每转脉冲数。用户换线后已有响应，但最终映射未确认，不沿用猜测。测试实例使用已确认的实际资源。

## 验收步骤

| 场景 | 操作与应观察结果 |
| --- | --- |
| 引脚首次配置 | 在 Studio 选择已支持的物理引脚，查看状态/预览 diff，确认应用后检查备份与“待重启”状态；重启后刷新，只有 helper 验证 pinmux、controller 映射和通道数后才可创建实例。未知启动链必须 fail closed。 |
| PWM 生命周期 | 对已验证且尚未 export 的通道创建实例，fanctl 应按需 export 并启动输出，记录 period/duty_cycle/enable 及 ownership ledger。禁用/删除应仅释放 fanctl 自己 export 的通道；对于预先已 export 的通道，确认不会 unexport。 |
| 初始零周期 | 在上述已验证、未被其他程序占用的通道上，清洁测试环境中让 fanctl 首次 export 后检查 period=0 初始化；创建实例无需手写 period，应正确初始化并输出。不要把正在工作的通道强改成零周期。 |
| 保存显示 | 创建后不刷新网页也出现正式实例，草稿消失，保存按钮防重复。刷新/重启后只保留一条同 ID 记录，无默认双风扇再生。 |
| 调速 | 短时 30%/90%，记录实际 duty/period、实物转速和 RPM；低速不转时区分风扇启动阈值。完成后恢复自动温控。 |
| 测速 | 转速变化对应 RPM；无 FG 或过期显示未知而不是 0。多实例采样时状态页仍可交互，不再因同步采样超时。RPM 绝对精度需参考仪器或可信基准另验。 |
| 生命周期 | 有效实例禁用/启用/删除即时反映状态；删除不再继续采样或重占服务自建 FG；只 unexport ownership ledger 明确登记为 fanctl 自己 export 的 PWM。 |
| 失效实例 | 用禁用记录和确认不存在的映射验证清理；不存在 PWM 可删除/禁用。不要制造真实生产权限故障；真实写失败需拒绝并保留诊断。 |
| 断连/忙碌 | 断连或模拟延迟不自动重放创建；已成功但刷新失败提示已保存、状态待刷新。结果未知时核对清单和 ID，勿重复创建。 |
| 自检与退出 | 自检后恢复原输出；重启服务无残留采样，恢复自动温控。检查日志、温度和线序，不以 ping 成功代替硬件健康。 |

## 证据与退出条件

记录每项通过/失败、实例 JSON、版本与包位置、服务日志、sysfs 读数、温度和实物观察。出现温度异常或控制失效立即恢复可靠散热并停止测试。

本地 Windows 回归使用模拟 sysfs/传输，不能证明 Linux Unix socket 权限、真实内核 PWM 写入约束、电气连线或 RPM 精度；这些由本轮真机验收补齐。zelux-pwm-setupd 只受控修改已 allowlist 的设备树 overlay 配置，不管理 PWM runtime；运行时 export/unexport 由 fanctl 独占负责。
